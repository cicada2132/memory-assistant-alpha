# 로드맵과 완료 조건

새 기능을 계속 늘리는 대신, 현재 기록 흐름을 재현 가능하게 만드는 순서다. 아래 일정은 확정 마감일이 아닌 작업 우선순위다.

## P0 — 해커톤 제출 전 근거 확보

- [ ] 합성 TXT 1개로 실제 Drive 스캔→후보 선택→블록 저장→검색→정정→삭제를 기록한다.
- [ ] 본인 계정과 다른 계정의 접근 결과를 각각 확인한다.
- [ ] AI 비활성/동의 거절 상태에서 외부 AI 요청이 나가지 않는지 실제 환경에서 확인한다.
- [ ] Gemini 상담 정상·오류·기록 없음 시나리오를 확인하고 공개 가능한 화면/영상만 남긴다.
- [ ] 음성 출력·마이크 입력을 기기별로 확인한다. 미작동 기능은 시연에서 제외한다.
- [ ] README·PROJECT·프롬프트 원칙 문서의 오래된 상태 표현을 정리한다.

완료 조건: 커밋, 실행 환경, 사용한 합성 데이터, 기대/실제 결과를 함께 남긴 재현 가능한 시연 1개. 실패 항목도 함께 기록한다.

## P1 — 입력부터 상담까지 연결

- [ ] RECORDS의 전사 결과를 후보 승인 과정을 거쳐 BLOCKS로 가져오는 경로를 만든다.
- [ ] 화자 본인 여부를 확인할 수 있게 한다.
- [ ] 사건시각/발화시각/저장시각 표시를 구별한다.
- [ ] 본문 정정 뒤 유형·인물·장소·작업 상태의 일관성을 확인한다.
- [ ] 후보 누락과 검색 실패를 합성 사례별로 측정한다.

완료 조건: TXT와 짧은 음성 파일이 같은 승인·검색·상담 흐름으로 이어지고, 원문/분석/본인 수정이 구별된다.

## P2 — 실제 운영 편의

- [ ] 휴대폰 → Drive 업로드 방식과 지원 기종을 확정한다.
- [ ] 기기 내 전사·요약이 실제 오프라인으로 가능한지 해당 기종에서 확인한다.
- [ ] 저녁 정리 실행 시점과 자동 생성/사용자 승인 범위를 명시한다.
- [ ] 하루 노트 내보내기 형식을 결정한다. 현재 JSON 외 Markdown 자동 저장은 별도 작업이다.
- [ ] 10분 입력 검증 후 1시간 범위의 파일 분할·누락·지연을 시험한다.

완료 조건: 자동화 실패를 발견·재시도할 수 있고 저장·전송 범위를 사용자가 이해할 수 있다.

## P3 — 연구와 로컬 우선 확장

- [ ] 주요 연구 자료를 주장-근거-한계 표로 재검토한다.
- [ ] 돌봄 전문가와 비임상 사용성 검토를 진행할 계획을 구체화한다.
- [ ] 로컬 저장·전사·개인 권한 구조로 옮길 부분을 결정한다.
- [ ] 사용자 연구의 질문·동의·중단·평가 절차를 별도로 설계한다.

활동 악화 예방, 치료 효과, 전용 하드웨어, 강한 감정 유도는 이 로드맵의 추가 기능으로 넣지 않는다.
