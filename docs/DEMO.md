# 해커톤 3분 시연안

이 문서는 예정된 시연 대본이다. 아직 촬영하거나 실제 배포에서 실행한 결과가 아니다. `examples/demo_261022_090000_original.txt`는 새로 작성한 합성 데이터이며 실제 환자 기록이 아니다.

## 시연 전 준비

1. 본인 전용 배포와 테스트용 저장 폴더를 확인한다.
2. TXT를 INBOX에 넣고 후보가 나오며 저장·검색되는지 예행연습한다.
3. 모리 상담은 선택적 후반부다. Gemini 설정·실제 응답을 먼저 확인한다.
4. 화면에서 계정 정보·실제 파일명·다른 기록·키가 보이지 않도록 테스트 데이터를 분리한다.
5. 실패하면 테스트 로그나 문서로 전환하고, 실제 동작하는 화면처럼 연출하지 않는다.

## 시간별 구성

| 시간 | 보여 줄 것 | 말할 내용 |
|---|---|---|
| 0:00–0:25 | 한 문장 문제 정의 | “기록을 남겨도 지금 무엇을 하려 했는지 연결하기는 어렵습니다. 과거 기록을 확인하면서도 현재 선택은 본인이 할 수 있는 도구를 만들었습니다.” |
| 0:25–1:00 | TXT 승인 대기·후보 | “자동으로 발견한 대화 전체를 기억으로 확정하지 않고, 저장할 문장을 선택합니다.” |
| 1:00–1:35 | ‘도서관에서 뭐 했지?’ 검색 | “출처가 있는 기록을 찾습니다. 외부 생성 AI 없이도 기본 검색을 사용할 수 있습니다.” |
| 1:35–2:00 | 정정 또는 작업 상태 변경 | “기록이 다르면 고칠 수 있고, 과거의 계획을 지금 중단할 수도 있습니다.” |
| 2:00–2:35 | 전송 미리보기→모리 상담 | “외부 AI에 보낼 내용을 확인한 뒤 하루를 이야기합니다. 캐릭터도 기록에 없는 기억을 만들어서는 안 됩니다.” |
| 2:35–3:00 | 검증과 다음 단계 | “현재 모의 테스트 25개를 통과했습니다. 실제 사용자 효과는 미평가이며, 다음은 입력부터 상담까지 통합 검증입니다.” |

## 사용할 질문

- “도서관에서 뭐 했지?” — 합성 기록의 도서관 발화 검색.
- “은행 가는 거 끝냈나?” — 처음에는 계획 상태를 확인하고 실제 완료 여부를 단정하지 않아야 함.
- “수영장 갔었나?” — 입력에 없으므로 확인된 기록이 없다고 답하는지 확인.

날짜가 고정된 TXT라면 상담 날짜를 2026-10-22로 고른다. 나중에 시연할 때 ‘오늘’로 검색하려면 파일명·날짜를 시연일에 맞게 일관되게 바꾼다. 상대 날짜 표현의 자동 정규화가 완성된 것으로 설명하지 않는다.

## AI가 작동하지 않을 때

기본 시연은 TXT 선택 저장·규칙 검색·정정으로 끝낼 수 있다. AI 대화는 문서의 구조도를 보여 주며 구현·모의 검사 상태를 설명한다. 합성 답변을 실제 Gemini 결과처럼 보여 주지 않는다.

## 심사 질문과 답변

**일반 AI 일기와 어떤 차이가 있나요?**

저장과 요약뿐 아니라 기록의 출처, 저장 승인, 자기정보 변경 승인, 과거 기록과 현재 선택의 충돌을 다룹니다. 차별점은 이를 실제 데이터 흐름으로 구현하려는 설계에 있습니다. 경쟁 제품 전체에 없는 기능이라고 주장하지는 않습니다.

**개인정보가 기기 밖으로 안 나가나요?**

현재는 GAS/Drive 기반 클라우드 알파입니다. Gemini는 선택적으로 사용하고 전송 확인을 거칩니다. 온디바이스 처리는 장기 방향입니다.

**치매 환자에게 효과가 있나요?**

아직 검증하지 않았습니다. 현재 결과는 코드와 모의 테스트이며, 먼저 실제 연결과 사용성을 평가할 계획입니다.

**왜 모든 내용을 자동 저장하지 않나요?**

편의와 함께 잘못된 발화·타인 발화·자동 요약이 본인의 기억 정보로 굳어지는 문제를 고려했습니다. 현재는 후보를 자동으로 찾고 사용자가 선택하는 구조입니다. 이 선택 부담도 평가할 항목입니다.
