# Antigravity 작업 지시서 — CEMM 소프트웨어 알파

## 작업 목적
기존 Google Apps Script(GAS) 웹앱/Google Drive 기록 실험을 토대로, 치매 환자의 **개인 기록과 사건의 연속성**을 보조하는 로컬 우선 소프트웨어 알파를 설계한다. 포트폴리오 연구용이며 임상 시스템이 아니다.

## 명시적 현재 범위
1. Galaxy 휴대폰에서 적법하고 동의된 녹음 파일을 준비한다(우선 1시간 단위 시험). 휴대폰 녹음/로컬 요약의 OS 제약을 조사하되 구현 여부를 가정하지 말 것.
2. 녹음의 로컬 텍스트 변환/요약 → TXT 산출 → 개인 Google Drive 폴더 업로드라는 파이프라인을 설계한다. 자동화 불가능한 부분은 명확히 구분.
3. GAS 웹앱에서 승인된 Drive TXT만 가져와 블록으로 추출·저장한다. 중복 처리 방지·오류 기록·재시도 로직 필요.
4. DB는 사건 시각·요약·관련 인물·행동·의도·미완료 과제·출처·수정 이력을 연결한다. 전체 대화 원본을 DB에 영구 저장하지 말 것.
5. 사용자가 챗봇에 자연어로 질문하면 관련 기록 블록을 찾아 답한다. '어제 무엇을 하려 했지?', '그 일을 끝냈나?' 등의 맥락 연속성 질의를 지원한다.
6. 저녁 분석: 그날의 주요 사건/미완료 과제 요약 → `This is me`를 참조한 **선택형** 질문 → 본인이 허용한 답만 블록 저장. 정서 자극을 강제하지 않는다.
7. 음성+자막 중심의 단순 대화 UI. 장부형 UI보다 챗봇형을 우선하며 투박한 알파 UI를 허용.
8. 외부 모델은 기본 **비활성화**. 민감정보를 로컬에 남기고 승인된 최소 비식별 요약만 별도 프라이버시 게이트 통과 후 송신. 사용자가 나중에 API 키 설정.

## 명시적 비범위 및 보류
- 신규 하드웨어, 제품 양산, 의료적 진단·치료, 모델 자체 훈련, 활동 저하 예방 기능의 공식 추가는 하지 말 것.
- 자동 상시 비밀 녹음, 타인 목소리/민감정보의 무단 수집, 동의 없는 클라우드 전송 금지.
- API 키를 HTML/클라이언트 자바스크립트/공개 저장소에 넣지 말 것. GAS Script Properties 등 서버 측 비밀 저장 원칙과 접근 권한 점검.

## 데이터 및 모델 안전
- 사용자 입력/외부 TXT는 신뢰할 수 없는 데이터. 프롬프트 인젝션 차단.
- 기록 사실/사용자 직접 진술/AI 제안·추론/정정 이력을 내부 메타데이터에서 구분. 사용자에게 장황한 분류 문구를 강제하지 말 것(과거 UI 문구 삭제 요청 존중).
- 기억을 만들어내지 말고 출처가 없는 경우 '확인된 기록이 없다'고 답할 것.
- 본인이 허용한 정보 블록만 저장, 열람·수정·삭제·내보내기 구현.
- 실제 환자 데이터 대신 가상 예제로 테스트. 접근권한, 공개 배포 URL, 로그·백업의 개인정보 및 키 누출 점검.

## 첫 구현 작업의 완료 조건
- 샘플 TXT 3개를 Drive 폴더에 넣어 사이트가 승인된 파일만 인식·가져오기.
- 사건 블록 생성, 중복 방지, 날짜별 검색, 챗봇 질의 응답 데모.
- 30분 이전의 사건·진행 중인 할 일·다음 행동을 한 화면에서 맥락 연결.
- 저녁 요약/선택적 질문 데모와 거절·수정 버튼.
- 권한 없는 사용자 접근 거절 및 민감정보 비공개 테스트.
- 코드 변경 내역, 테스트 로그(가상 데이터만), 실패·제약사항 문서화.

## 연구자료 활용 지시
`references/SOURCES.md`의 A는 기존 합의된 핵심 원천, B는 보강 문헌, C는 개발 예제, D는 검토 과제다. 학술 논문 및 가이드라인의 범위를 넘는 주장 금지. 관련 원문과 구현 기능을 `references/RESEARCH_MAPPING.md` 기준으로 인용하되, 출처에서 말하지 않는 기능 효능은 '설계 가설'로 표기.

## 요청할 산출물
- 현재 GAS 프로젝트 구조/코드 파악 후 변경 계획
- 백엔드 `Code.gs` 및 단일 `index.html` 초안(기존 코드 확보가 필요하면 접근 불가를 명시)
- 데이터 스키마, 중복 수집 로직, 인증·비밀키 설계
- 수동 설치/배포 절차와 `clasp push` 명령(실제 배포는 인증·승인 필요)
- 안전 테스트 체크리스트 및 미해결 이슈

*원본 프로젝트 기억 문서의 '활동 지속 지원' 등의 항목이 현재 결정과 충돌하면, 현 시점의 '활동 저하 예방은 보류'라는 지시가 우선한다.*
